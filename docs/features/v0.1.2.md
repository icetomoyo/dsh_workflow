# v0.1.2 — Reliable handoff preflight and background lifecycle

## Feature_003: Reliable handoff preflight and background lifecycle projection

### Problem

An inline workflow handed off by `/workflow` previously consumed its one-shot grant as soon as the engine started. A task-field error reached only by the restricted script (such as `modelHint: "powerful"`) could therefore fail after the grant was gone; in a DSH session configured with approval prompts disabled, a corrected retry was then denied. Separately, native workflow events inherited the tool step that launched a background run, so DSH Web projected the still-running process as interrupted when that step closed.

### Contract

- A command-authored capsule executes once with inert smoke agents before `startInline` and before the one-shot grant is consumed.
- Smoke child inputs use the engine's shared task-shape and deterministic admission validators. Invalid task metadata, read-only violations, unavailable provider capabilities/adapters, dynamic agent limits (including synthesis), single/concurrent token reservations, nested workflow names and inputs, input schema, and parallel concurrency start no real child and do not consume the same-turn grant.
- The relay authoring prompt enumerates the closed model tier vocabulary: `fast`, `balanced`, `deep`.
- A valid first inline start consumes the grant atomically. Repeated valid starts, later human messages, forged context, and later turns remain fail-closed.
- Dynamic `tool-workflow/run-start` events carry explicit Session ownership (`turn: null`). DSH Web keeps the run live across tool-step and turn closure; the matching `run-end` remains the sole terminal fact.

### Verification

- Regression tests: invalid later-phase `modelHint`, explicit-null branching, read-only violation, dynamic agent/synthesis limits, single and concurrent token reservations, nested workflow resolution, input schema, and parallel concurrency reject before `startInline`; a corrected same-turn source still receives the one-shot grant.
- A mutually exclusive two-call-site workflow with `maxAgents: 1` passes when its exact args execute only one branch, proving the smoke limit is dynamic rather than a false-positive static call-site count.
- Engine event test: native `run-start` contains explicit Session ownership.
- DSH compatibility verification: its real Conversation assembler keeps a session-scoped workflow and member `running` after both the launching step and turn close; the retained plugin regression asserts the emitted Session coordinate.
- Full plugin suite, typecheck, build, compatibility pin, and packed-entry smoke must pass.
