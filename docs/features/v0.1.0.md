# v0.1.0 — DSH Dynamic Workflow Harness

## FEATURE_001: KodaX-parity workflow orchestration

### 1. 需求概述

为 DeepSeek Harness 提供完整的 workflow 产品层：可复用与动态生成 workflow、capability-only 脚本运行时、多 Agent 编排、生命周期控制、持久 run graph、重跑/续跑、发现、审批/预检、内置模板、斜杠命令和模型工具。

实现采用 clean-room 方式。KodaX 是行为与能力参考；执行、生命周期、持久化和产品集成都基于 DSH 扩展点独立实现。

### 2. 影响范围

- 可发布 bundle `@dsh-external/workflow` 与 `cordis.patch.yml`。
- Cordis service `ctx.dynamicWorkflows`、三个模型工具、`/workflow` 命令和 system prompt policy。
- project/personal workflow catalog、两个 built-in 和六个 pattern。
- restricted capsule 与显式批准的 trusted-local `.ts/.mjs/.js` module。
- DSH provider、structured output、tool restriction、model route、cancel、approval、background job 和 native Session/UI event。
- 每项目 durable run graph、effect cache、artifact、summary、cost 与 provenance。
- 发布时对最新 DSH 默认 snapshot 做兼容 pin、打包和 profile 安装 smoke test。

### 3. 技术方案

#### 3.1 Clean-room architecture

插件不替换 DSH agent loop 或原生 `ctx.workflows`。KodaX WorkflowApi 需要 durable task handle、live messaging、pause admission、nesting、budget 和 artifact，这些职责位于 DSH 前台 worker seam 之上，因此插件基于 `ctx.subagents` 增加独立 process/service 层。

生成型 `.workflow.json` capsule 运行在 QuickJS WebAssembly 独立堆。静态 policy 拦截 host API，所有 effect 通过 JSON RPC boundary 进入冻结 WorkflowApi；CPU slice、墙钟、内存和栈都有上限。trusted-local module 是不同 trust class，只在显式批准后 import。

#### 3.2 Public WorkflowApi

- Identity/input: `runId`, `args`, `budget.total/spent()/remaining()`。
- Structure: `phase`, `parallel`, `pipeline`。
- Agents: `spawnAgent`, `runAgent`, `wait`, `snapshot`, `output`, `send`, `stop`。
- Composition: `synthesize`, 单层 `workflow(name,args)` nesting。
- Evidence: `artifact`, `log`。
- Policy: phase/name/prompt、scope/constraints、readOnly、provider/model/fast|balanced|deep、maxTokens/effort、output schema、evidence refs、verification、terse result、shared cwd/worktree。

#### 3.3 Lifecycle/durability

run 状态为 `running|paused|completed|failed|denied|stopped`。pause 阻塞尚未 publish 的 child，resume 放行，stop abort 并 dispose active child。状态通过 service subscription、tools、commands、DSH background job 和原生 `tool-workflow/*` Session event 暴露。

run store 保存 metadata、append-only events、script/manifest snapshot、JSON artifact、per-effect cache 与 terminal cost summary。按 run id 重跑使用 immutable snapshot；resume 可回放相同 effect；按 saved name 重跑使用当前 capsule。

#### 3.4 Discovery/authoring/safety

project `.dsh/workflows` 覆盖 personal `$DSH_HOME/workflows`；同目录 capsule 优先于 trusted-local source。symbolic link、traversal name、oversize file、unknown field、unsupported version 和 invalid manifest 都在执行前拒绝。

`create` 使用 scout-then-author：只读 scout 收集 workspace 事实，structured-output author 生成 capsule，再经过最多三次 repair、source policy、quality lint、manifest limit、capability preflight 和 approval。`revise` 保留 provenance 并 archive 旧 capsule。

### 4. 接口契约

- Capsule: `format: "dsh.workflow"`, `version: 1`, `workflowApiVersion: 1`, `minDshVersion`，以及严格 manifest/source/intent/inputs/requires/provenance。
- Service: list/load/start/create/revise、runs/show/pause/resume/stop/delete/prune/rerun/save/rename、subscribe、isolation/verification/dispatch adapter registration。
- Tools: `workflow_list`, `run_workflow`, `workflow_manage`。
- Command: `/workflow [help|list|create|runs|show|pause|resume|stop|delete|prune|rerun|resume-run|save|rename|revise|<name>]`。
- 任何能力不得被静默忽略。缺少 provider capability、adapter、可计量 budget route、approval/user interaction 或 requirement 时 fail loud。

### 6. 验收标准

- [`docs/KODAX_PARITY.md`](../KODAX_PARITY.md) 每行都已实现，或由于 DSH 当前 seam 不存在而提供等价 public adapter + fail-loud gate。
- restricted script 无法直接访问 process、filesystem、network、import、timer、dynamic code、randomness 或 wall clock。
- agent start 遵守 cap、concurrency、provider capability、route、budget、read-only、schema、cancel 和 verification。
- run 可在发起命令/工具返回后继续观察和管理；终态 resource quiescent，durable record 自包含。
- discovery、save/revise/replace、identity、snapshot rerun、cache resume、delete/prune deterministic 且 path-safe。
- built-in 与六种 pattern 使用相同 runtime 和 governance path。
- tarball 能安装进 clean DSH profile；compatibility、test、coverage、typecheck、build、pack 与 smoke test 均通过。
- README 清楚说明对 DSH 的价值：将一次性 orchestration 转为可复用、可治理、可观察、可恢复的 workflow 资产，同时复用 Harness 既有基础设施。
